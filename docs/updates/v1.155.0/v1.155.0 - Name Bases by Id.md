# Azgaar's Fantasy Map Generator v1.155.0: Name Bases by Id

Name bases have always been identified by their position in the list. That is invisible until the
list changes: adding a base before an existing one shifts every later base, so cultures on saved maps
begin naming their towns and states from a different corpus. Renaming a base was safe, but its place
in the list was its identity, and positions are not names.

Version 1.155.0 gives every name base a permanent five-letter **id** — `GERMA` for German, `ELVEN` for
Elven, `TRKCO` for Trek Core — and makes cultures reference that id instead of a position. Position is
now only how the editor lists the bases. A base keeps its corpus when it is renamed, when bases are
added around it, and when a downloaded base set is imported on another machine.

The Namesbase Editor writes ids into downloaded files (`id|name|min|max|d|m|names`) and uploads them
back with the same identities. Files without the id column, including the community packs already in
circulation, still load: the id is derived from the base's position or name, so nothing is lost.
Generated bases get an id derived from their name.

Existing maps load unchanged. The loader recognises the old position-based format, assigns each base
the id of the shipped base that used to sit at its position, and rewrites every culture's base
reference through the loaded list — the same corpus as before the update. The `.map` file keeps the
same slot for name bases, so a map saved here can be opened by this version without conversion and
old maps need no separate step.

For the generator, this is groundwork: new culture sets can bring new name bases without disturbing
the ones already on the map.
