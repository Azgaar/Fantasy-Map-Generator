# Azgaar's Fantasy Map Generator v1.154.0: Icon Library

The previous release added illustrated settlements, engraved terrain and new map styles. But choosing artwork still depended on what you were editing. Goods had their own uploader, markers and regiments shared another selector, and burgs used a separate collection. A picture available in one editor could be unavailable in another.

Version 1.154.0 brings those systems together. The new Icon Library makes artwork reusable across the map, including in generated relief and emblems. Alongside it, the Style Editor has been rebuilt, and the Assistant can now work with the data in your world. Much of this release is about connecting parts of the Generator that previously worked in isolation.

## Icon Library and custom artwork

The old icon system had a storage problem as well as an interface problem. An uploaded marker image was copied into every marker that used it. A hundred markers could mean a hundred copies of the same picture in the map file. Replacing that artwork was also different from changing an uploaded goods icon or a burg symbol.

Custom pictures now belong to the map's **Icon Library**, and map objects refer to them. Upload a seal once and use it for a state, its capital and its regiments. Replace the library image later and all of those uses follow. Older maps are converted on load, with repeated uses of the same image sharing a library entry.

The same change removes the restrictions between icon collections. A heraldic dragon can become a marker, a goods icon can represent a regiment, and an uploaded drawing can stand in for a mountain. Built-in artwork, emoji and short text are available through the same picker. The Illustrated settlement collection has also expanded, and burg and port symbols are now chosen together under **Style → Icons**.

Bringing in your own art needed more than an upload button. Pictures often arrive with uneven margins or too much empty space, which makes them look tiny or off-center on a map. Uploads are now fitted to their visible content, with a position editor for adjusting the frame. That adjustment belongs to the picture too, so it fixes every use at once.

There are still two ways to store custom art. Uploading an SVG, PNG, JPEG or WebP keeps it inside the `.map` file and makes it available offline; raster uploads are resized to limit file size. Linking stores only the address, but the image must remain available from its host, and raster exports can include it only when that host permits access. The library carries over when generating another map. Loading a saved map brings in that map's own library.

Emblems benefit from this shared artwork as well. An icon can be used as a charge on a shield, with field and charge colors, or as the whole emblem for a flag, badge or finished coat of arms. **Edit in Armoria** now links the two windows, so changes there appear on the map, including undo, redo and tincture edits. Custom library pictures remain a Generator feature and are edited through its picker.

## Biome relief rules

Each biome now has an editable **relief pool**: a list of icons with weights that determine how often each is picked, and sizes that set how large each is relative to the others. A sample patch previews the pool as the map draws it while you edit. A grassland can contain mostly grass with a few trees; a woodland can mix ordinary and dead trees. Pools accept any library icon, so custom art follows the same placement process as the built-in relief. They are opened from the Biomes Editor's Relief column.

Hills and mountains need more than a biome setting. Their placement now follows editable rules with elevation and temperature ranges, optional biome restrictions, and their own pools, sizes and densities. This allows desert hills to differ from forest hills, or snowy peaks to begin at a chosen temperature. Rules run in order, with the first match taking precedence; land no rule claims uses its biome's pool.

Editing these settings does not immediately replace the relief you have already arranged. Re-placement is a separate action, limited to the affected area, so work elsewhere is kept. The rules also carry over to newly generated maps.

The artwork itself remains separate from placement. Switching relief sets redraws the existing icons without moving them, while individual icons can stay pinned to a particular set. **Stickers** is the new addition alongside Simple, Colored, Gray and Illustrated.

## Making style changes easier to follow

The previous update notes named the Style Editor and its presets as the last legacy modules still waiting for migration. That work is now done: both have moved to TypeScript, retiring the remaining scripts in `public/modules`.

The editor now builds its controls from the same definitions used to store and validate the map's style. A setting no longer needs a separately maintained form just to become editable. This also gave the Style tab a more consistent layout: related controls sit in folding cards, with previews of their colors, lines, fonts and filters in the headers.

For someone working on a map, the more useful change is being able to see what has been altered. Values that differ from the selected preset are marked in red and can be reset individually. If a border color or label size no longer works, restoring it does not discard the rest of the styling.

Choosing a starting style is more visual too. The preset gallery shows each built-in preset on the same map, and **Atlas** has been reworked. The Style elements browser helps with the next step: finding a particular layer or group, seeing how many objects use it, and turning it on while editing.

## An Assistant that can read the map

Documentation can explain how the Generator works, but it cannot answer which states on your map have no ports or which burgs have the largest populations. Those questions require access to the world itself. With your own AI key or a local model, the Assistant can now read that data, calculate answers and export results as CSV or JSON. From the Notes Editor, it also receives the open note and selected text as context for writing.

Editing adds another requirement: a request in chat needs to become a change you can inspect. The Assistant therefore produces proposals with **before → after** values, including related changes to labels and territory. A proposal waits for **Apply**; it can be discarded, and an applied batch can be undone. If subsequent edits make either operation outdated, the card shows **Changed since** and disables it.

This matters for operations that affect more than one visible object. Renaming a state can affect its label and full name; merging states changes ownership and other related data. The proposal puts those changes together for review. When a request is missing a necessary detail, such as where a new state should be, the Assistant can ask before proposing it.

Its editing scope includes names, notes, emblems, populations, diplomacy and territory, as well as creating or removing entities and merging states or provinces. It can restyle the map too, since every Style tab value goes through the same proposals: ask for a darker sea or a different label font and Apply it like any other change. Heightmap editing, relief and ice remain in their editors. Conversations are kept in the browser and associated with their map, so loading or generating another world starts a new chat.

Map access requires **Use key**, which connects Anthropic, OpenAI, Mistral, Qwen, DeepSeek or a local model. Keys stay in the browser and go directly to the provider. The free Assistant on the official site continues answering documentation questions, with a larger daily allowance after signing in through Discord; it cannot read the map. Desktop and self-hosted copies use a key or local model.

## Smaller changes to everyday editing

Diplomacy is easier to edit geographically. The new brush in the Diplomacy Overview lets you select a reference state and paint relations onto its neighbors, updating both sides of each relationship. Strokes can be undone or discarded before the changes are committed to diplomatic history. State merging also has a useful new option: each absorbed state can become a single province, preserving its former territory within the larger state while replacing its internal provinces.

Saving now behaves more like saving a document. Where the browser supports it, the first **Save → Machine** chooses a file, and later saves write directly to it. **Ctrl/Cmd + Shift + S** chooses another destination. Loading or generating a different map resets the destination; browsers without a save-location picker keep the download behavior.

Several fixes address smaller interruptions: removing a market center's plaza now offers to remove its market, the citadel controls work again, and assignment brushes follow the pointer correctly. Filtered image exports no longer clip when zoomed out, exported icons retain their sizing more reliably in SVG editors, and broken ocean-pattern references in older maps are repaired on load. Province reassignment also avoids choosing a neighboring province from the wrong state.

Older supported `.map` files continue to load and upgrade automatically, including their existing icons and styling.
